## 测试口径

- 目标模型：`deepseek-v4-flash-0731`；网关：`https://tokenrhythm.studio/v1`，接口 `/chat/completions`。
- 从 710 条活动句子中，用 `random.Random(20260907).sample` 无放回随机抽取 100 条。
- 固定这 100 条反复测试，不因句子难或结果差而换样本。
- 每条均检查英文原文、中文译文、重点词和双语阅读块；不把数据库旧译文或其他模型的评分当标准答案。
- 评测脚本以 SQLite `mode=ro` 读取数据库，候选仅写入审计报告，不批量覆盖学习内容。
- 请求参数：温度 `0.2`、超时 `180s`、同一进程共享 `18` 次/分钟的节流、瞬态错误最多重试 `2` 次；不发送额外推理强度参数。

## 已落地的机制

1. **整句与展示分离**：先提取必要语义锚点、翻译，再独立终审；高风险并列结构从英文结构独立重译，避免只在坏草稿上换词；锁定整句后才生成词卡和分块。
2. **真实上下文**：仅提供相邻英文辅助消歧；不把相邻句的背景事实或旧中文译文塞进目标译文。
3. **定稿约束词卡**：词卡必须引用原英文和最终中文的连续文字；不能引用已被修改的草稿。
4. **局部修复**：只重做引文或格式不合格的词卡，最多两次；正确卡片不因重试而反复变动。
5. **词义边界**：区分词本身、习语整体、相邻修饰词及否定；少量有明确语境条件的词条、指代在本地校准，改动记录在 `term_repairs` 中，并在词卡生成前完成。
6. **按原文定位分块**：模型返回双语短语锚点，程序截取连续文本；不让模型数 token，也不允许分块改写译文。
7. **保守回退**：无法逐块对齐或条件与主句调序时保留整句一块，宁少切、不错误配对。
8. **可解释检查**：对已复现的否定、比较、情态、修饰范围和不完整边界进行定向检查，触发有限修复，不静默接受失败候选。
9. **网关保护**：共享节流、429/瞬态故障退避、鉴权和模型错误不盲目重试，诊断中的密钥脱敏。

代表性问题不是单纯换中文措辞：

- `less of a setback` 应保留挫折程度较小，不能变成发生挫折的概率较低。
- `somehow` 是“以某种方式 / 不知为何”，不是 `somewhat` 的“在某种程度上”。
- `high-profile` 是备受关注，不是高级别；`food police` 不自动成为政府机构。
- `sustainable` 即使在否定句中仍表示可持续的；否定属于外围结构。
- `slot`、`suit` 不单独等于老虎机、效仿；`checked-baggage` 不包含邻词 `fees` 的费用义。
- `only if` 的条件和主句在中文调序后不能强行逐块拆开；`United` 不能仅因以 `ed` 结尾就被当作谓语动词。

## 审计与限制

`backend/data/audits/deepseek-flash-20260907/`；逐句观察见其中的 `review-notes.md`。
该目录和实际密钥配置不进入 Git。复现命令见项目 README 的“翻译质量评测”。
